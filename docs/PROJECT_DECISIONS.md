# AutoMind — проектные решения (дополнения к ТЗ)

Документ фиксирует решения по недочётам ТЗ, согласованные с заказчиком 01.11.2026.
Базовый документ: `AutoMind_ТЗ.docx` v1.0. При противоречии приоритет — у ТЗ, кроме пунктов ниже.

## 1. Таблица economic_settings расширена (ТЗ 7.2.10 + 4.3.3)

7 параметров вместо 5:

| Поле | Назначение |
|---|---|
| `fuel_price` | стоимость литра топлива, ₽/л |
| `default_fuel_consumption_rate` | нормативный расход топлива по умолчанию, л/100 км (у конкретного автомобиля его значение приоритетнее) |
| `driver_hourly_rate` | стоимость часа работы водителя, ₽/ч |
| `maintenance_rate` | стоимость обслуживания километра, ₽/км |
| `additional_cost` | дополнительные переменные расходы, ₽ |
| `toll_cost` | платные дороги, ₽ |
| `other_cost` | прочие расходы / доп. расходы на эксплуатацию транспорта, ₽ |

## 3. Нормализация частных оценок 0–100 (ТЗ 5.8)

- Min-max нормализация внутри набора кандидатов конкретного заказа.
- Критерии «меньше — лучше» (ДТП, нарушения, штрафы, расход) инвертируются.
- Если кандидат один — все частные оценки = 100.
- При отсутствии истории рейсов (ТЗ 5.6) — нейтральное значение 50 и флаг
  `insufficient_data = true`; расчёт ведётся по нормативам автомобиля.

## 4. Формулы RISK_SCORE и RELIABILITY_SCORE

- `RELIABILITY_SCORE = (рейсы последних 10 без ДТП/нарушений) / (всего завершённых из последних 10) × 100`
- `RISK_SCORE = 0.5 × norm(ДТП) + 0.3 × norm(нарушения) + 0.2 × norm(штрафы на рейс)`, 0–100.
  Чем выше, тем рискованнее кандидат. Отдельно учитывается `fault_status`: ДТП без вины
  водителя не увеличивают риск.

## 5. Веса критериев — в БД

Таблица `scoring_weights`: `(id, criterion, weight_percent, cargo_type)`.
`cargo_type IS NULL` — базовый набор весов. Дефолт по ТЗ 5.8:
экономика 35 / ДТП 25 / нарушения и штрафы 15 / расход топлива 15 / надёжность 10.

Правило хрупкого груза (cargo_type = FRAGILE): экономика 25 / ДТП 35 / нарушения 15 /
расход топлива 10 / надёжность 15 (сумма 100).

## 16. Карта — Яндекс Карты (изменение от 02.11.2026, требование заказчика)

Основной картографический провайдер — Яндекс Карты JS API 2.1 (`YandexMap.tsx`).
Ключ хранится во frontend-переменной `VITE_YANDEX_MAPS_KEY` (файл `frontend/.env`,
получение — developer.tech.yandex.ru). При отсутствии ключа или ошибке загрузки
автоматически используется fallback на Leaflet/OpenStreetMap (`FleetMap.tsx`) —
ТЗ 4.6 допускает «другой совместимый вариант». Смена провайдера не влияет на
backend: координаты маршрутов и телеметрия хранятся в БД провайдер-независимо.

## 17. Комплаенс: законодательство РФ о сайтах и сервисах

Реализовано в продукте (02.11.2026):
- Политика в отношении обработки персональных данных (152-ФЗ) — встроена в UI;
- Пользовательское соглашение (149-ФЗ, ограничение ответственности, статус MVP «как есть»);
- баннер согласия на обработку cookie (`ConsentBanner`, фиксируется в localStorage);
- код доступа только в виде BCrypt-хеша; БД при деплое в РФ — на серверах в РФ.

Организационные шаги вне кода: уведомление Роскомнадзора об обработке ПДн,
заполнение реквизитов оператора (плейсхолдеры в `Legal.tsx`), договоры/оферта
при коммерческом запуске, согласование текстов с юристом. Тексты — шаблоны,
не юридическая консультация.

## 16а. Дорожные маршруты — OSRM (дополнение от 02.11.2026)

Дорожные маршруты «как в навигаторе» строятся через OSRM — открытый
маршрутизатор на данных OpenStreetMap (публичный демо-сервер
router.project-osrm.org, без ключа). Цепочка источников: OSRM →
маршрутизатор JS API → HTTP Роутинг API Яндекса (платный — не подключён) →
прямые линии. Маркеры прижимаются к геометрии дороги; клик по автомобилю
приближает карту к его дорожному маршруту. Атрибуция «OSRM · © OpenStreetMap
contributors» выводится на карте. Для продакшена без лимитов: свой OSRM в
Docker (`osrm/osrm-backend` + выгрузка карт РФ с Geofabrik) либо платный
«Маршрутизатор» Яндекса.
